# NNNN: 判断を表す短いタイトル

- Status: Proposed
- Date: YYYY-MM-DD
- Supersedes: なし
- Superseded by: なし

## Context

どの全体アーキテクチャ上の問題を解くのかを書く。要求、制約、既存の境界を示すが、
関数、型、シグネチャ、行番号、細かな制御フローは書かない。

## Decision

選んだ構造、境界、不変条件を、実装者が従える粒度で書く。

## Alternatives considered

- 代替案と採用しなかった理由

## Consequences

### Positive

- 得られる性質

### Negative

- 引き受けるコストや制約

### Follow-up

- 同じ変更で更新すべき現在設計、移行、検証
