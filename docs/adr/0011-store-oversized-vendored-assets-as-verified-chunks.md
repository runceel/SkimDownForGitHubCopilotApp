# 0011: 上限を超える vendored 資産をチャンクとして同梱し、配信時に結合する

- Status: Accepted
- Date: 2026-07-31
- Supersedes: なし
- Superseded by: なし

## Context

GitHub Copilot app の拡張インストーラーは、1 ファイルあたりのサイズ上限を持つ。
上限を超えるファイルが 1 つでもあると、拡張全体のインストールが失敗する。
同梱している mermaid の配布物はこの上限を大きく超えており、公開したバージョンを
リポジトリフォルダー URL からインストールできなかった。

一方で、この拡張は 2 つの既存判断に縛られる。ADR 0009 は vendored 実行資産の取得元と
byte 列を固定し、CI で上流と照合することを求める。ADR 0001 と 0006 は、上流 renderer を
原則としてそのまま同期し、ホスト差分を互換レイヤーへ寄せることを求める。したがって、
上限への対応がバイト単位の再現性を失わせたり、renderer から見える資産の参照方法を
変えたりしてはならない。ADR 0008 の renderer origin は外部 origin への接続を許可しないため、
実行時に外部から取得する解法も取れない。

## Decision

上限を超える vendored 資産は、**保管形態だけ**を変える。上流バイト列を固定長のチャンクへ
分割して同梱し、renderer origin のサーバーが要求時に結合して配信する。renderer から見える
資産のパス、MIME、バイト列は上流と同一のままとする。

固定台帳は、資産ごとに**結合後の SHA-256（＝上流バイト列）とチャンク個別の SHA-256、
チャンク長**を持つ。検証は、チャンク単体の一致に加えて、結合結果が上流取得元と一致することを
必ず確認する。台帳が資産の保管形態の正であり、配信側は台帳から結合対象を導く。

チャンクは内部的な保管単位であり、renderer origin から個別に配信しない。
また、同梱物に含まれる全ファイルがインストーラーの上限以下であることを、
vendored 資産の検証とテストの両方で強制する。

## Alternatives considered

- **該当コンポーネントを同梱から外す**: 図の描画という利用者向け機能を失う。
- **実行時に外部 CDN から取得する**: renderer origin の接続禁止とオフライン動作の前提に反し、
  新しい信頼境界を実行時に増やす。
- **圧縮した単一ファイルとして同梱し、転送エンコーディングで復元する**: 圧縮後サイズが上限に
  近く、エンコーダーの実装差で出力バイト列が変わるため、固定取得元からの再現検証ができない。
- **上流と異なる分割配布形態（ESM チャンクなど）へ差し替える**: renderer 側の読み込み方法を
  変更する必要があり、上流同期の前提を壊す。

## Consequences

### Positive

- 上限を超える依存物を同梱したままインストールできる。
- 上流バイト列との一致を、結合後ハッシュとして引き続き機械検証できる。
- renderer と CSP、origin の構成を変えずに済み、オフライン動作を維持できる。
- 上限超過の再発を、公開前の自動検証で検出できる。

### Negative

- 台帳と検証、配信経路が、資産の保管形態を意識する必要がある。
- 配信時に結合とメモリ常駐のコストを負う。
- 上流の更新でチャンク数が変わるため、更新手順は古いチャンクの整理を伴う。

### Follow-up

- インストーラーの上限が変わった場合は、上限値の定義箇所と検証を同時に見直す。
- 別の資産が上限を超えた場合も、個別対応ではなく同じ保管形態で扱う。
