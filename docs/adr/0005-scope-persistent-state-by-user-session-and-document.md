# 0005: 永続状態をユーザー、セッション、文書の同一性で分ける

- Status: Accepted
- Date: 2026-07-30
- Supersedes: なし
- Superseded by: なし

## Context

拡張が扱う状態には、パネルが開いている間だけ必要な接続、セッション固有の文書と選択、
複数セッションで共有したい読書設定がある。GitHub Copilot app の workspace はユーザーの
git worktree であり、実行時状態をそこへ保存するとリポジトリを汚す。

また、`instanceId` はパネルのルーティング用であり、provider reconnect や新しいパネルでも
同じ文書を表す永続 ID ではない。

## Decision

実行時状態と診断は `$COPILOT_HOME` 配下へ保存し、リポジトリへ書かない。

- ユーザーの読書設定と上限付き診断はユーザースコープに置く。
- インライン文書、セッション中に扱った文書、最後の選択は `sessionId` で分離する。
- ファイル文書はファイルパス、インライン文書はセッション内の安定 ID で識別する。
- `instanceId` は開いているパネルと action のルーティングにだけ使い、永続状態のキーにしない。
- パネル固有の server、購読、監視はメモリ上に置き、close とともに破棄する。

## Alternatives considered

- **worktree 内へ設定と状態を保存する**: ユーザーのリポジトリを汚し、セッション固有情報を
  project content と混同するため採用しない。
- **すべてをユーザーグローバルにする**: セッション文書と選択が別セッションへ漏れるため採用しない。
- **`instanceId` で永続化する**: パネルの再作成と文書の同一性を結び付けられず、
  reconnect 後の復元も不安定になるため採用しない。
- **すべてをメモリだけに置く**: provider reconnect 後にセッションの読書文脈を復元できないため採用しない。

## Consequences

### Positive

- 実行時状態が git 差分へ現れない。
- セッションの文脈とユーザー設定を、それぞれ適切な寿命で復元できる。
- パネルの再作成と文書の同一性が分離される。

### Negative

- `$COPILOT_HOME` 配下の移行、破損、清掃を考慮する必要がある。
- ファイル移動は文書同一性の変更として扱われる。

### Follow-up

- 新しい状態を追加するときは、panel、document、session、user のどの寿命に属するかを先に決める。
- 新しい永続状態を `instanceId` へ結び付けない。
