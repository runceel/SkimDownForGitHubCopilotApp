# 0006: セッション履歴の永続化を明示的かつ期限付きにする

- Status: Accepted
- Date: 2026-07-30
- Supersedes: [0005](0005-scope-persistent-state-by-user-session-and-document.md)
- Superseded by: なし

## Context

セッション状態にはインライン Markdown の本文、ユーザーが扱ったファイルのパス、最後の選択が
含まれる。これらをセッション終了後も無期限に平文保存すると、再接続時の復元性と引き換えに、
ユーザーが意図しない機密情報を端末へ残す。

保存先を worktree から分離し、セッション ID で隔離するだけでは、保存への同意、残存期間、
ユーザー自身による消去というデータライフサイクル上の要件を満たさない。

## Decision

セッション履歴は実行中の拡張プロセスのメモリを既定の所有場所とし、端末への永続化は
ユーザーが明示的に有効化した場合だけ行う。

永続化を許可された履歴にも必ずユーザー選択の上限付き保持期間を付け、期限切れデータを
自動削除する。保存を無効化したとき、またはユーザーが消去を要求したときは、本文と
メタデータを同じ保存境界から削除する。保持期限を証明できない旧形式の履歴は移行時に削除する。

消去の境界は SkimDown が所有する履歴に限定し、ホスト管理のセッション成果物と
リポジトリ内 Markdown の原本は削除しない。

## Alternatives considered

- **常に保存し、固定期間だけ保持する**: 無期限保存は避けられるが、本文とパスを端末へ
  書くことへの明示的な同意を得られないため採用しない。
- **セッション終了時にだけ削除する**: プロセスの異常終了や終了通知の欠落で残存し得て、
  再接続時の復元を希望するユーザーにも選択肢を提供できないため採用しない。
- **履歴を暗号化して無期限保存する**: 端末上の露出は減るが、保存への同意、最小化、
  保持期間、消去の問題は解決せず、鍵管理という別の境界も増やすため採用しない。
- **セッションごとに毎回許可を求める**: 最小権限には近いが、頻繁な確認で読書体験を
  損なうため、ユーザースコープの設定と明示的な消去を採用する。

## Consequences

### Positive

- セッション本文とパスが、ユーザーの操作なしにセッション終了後まで残らない。
- 永続化を選ぶユーザーは復元性を保ちながら、保持期間と消去を制御できる。
- 旧形式や期限切れのデータが将来にわたり蓄積しない。
- 消去対象が拡張所有データに限定され、原本を誤って破壊しない。

### Negative

- 既定設定では、プロバイダ終了後にインライン文書と選択を復元できない。
- 保存層は期限、移行、設定変更、明示的消去を一貫して扱う必要がある。
- ユーザー設定とセッション履歴のライフサイクルが連動する。

### Follow-up

- 新しいセッション由来データを追加するときは、本文と同じ opt-in、保持期限、消去境界へ含める。
- ホスト管理成果物と拡張所有履歴の消去境界を UI と設計文書で明示し続ける。
